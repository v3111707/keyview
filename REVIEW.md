# KeyView: ревью кода

Дата: 2026-11-20. Проверен коммит `9cef03a` (весь код в `Sources/KeyView`, тесты, `build.sh`, `Package.swift`).

Критичных багов нет. Есть четыре реальные проблемы и несколько мелочей. Ни одна пока не исправлена.

## Баги

Все четыре найдены чтением кода. Вживую они не воспроизводились: внешней клавиатуры не было, а нажатия клавиш не имитировались.

### 1. После скрытия и показа окна может рисоваться не та клавиатура

Важно только при двух клавиатурах разных типов (например, встроенная ISO и внешняя ANSI).

- При показе окна тип клавиатуры сбрасывается на системный (`App.swift:62`). Монитор нажатий при этом помнит старый тип и сообщает только об изменении (`KeyMonitor.swift:68`).
- Сценарий: печатаешь на внешней ANSI, скрываешь и показываешь окно. Окно может вернуться к ISO и остаться таким, пока не нажмёшь клавишу на другой клавиатуре.
- Исправление: хранить тип клавиатуры в одном месте.

### 2. Подсветка может залипнуть

- Клавиша гаснет только по событию «отпущена» (`KeyMonitor.swift:72-74`). В полях паролей и на экране блокировки macOS нажатия не отдаёт, поэтому это событие теряется.
- Сценарии:
  - перешёл по Tab в поле пароля — Tab остаётся подсвеченным;
  - заблокировал экран через ⌃⌘Q — после разблокировки горит Q;
  - так же может залипнуть слой Shift.
- Исправление: пока есть подсвеченные клавиши, раз в полсекунды сверять их с реальным состоянием клавиш.

### 3. Сочетания с fn не подсвечивают клавишу

- fn+стрелки, fn+⌫ и fn+↩ приходят с другими кодами (Home, End, Page Up, Page Down, Forward Delete, Enter). Поэтому горит только fn.
- Исправление: таблица соответствий на шесть кодов.

### 4. Нет повторной попытки после выдачи разрешения

- Перехват нажатий запускается один раз при старте (`KeyMonitor.swift:28`). Если в диалоге macOS нажать «Позже» вместо «Quit & Reopen», подсветки не будет до перезапуска.
- Исправление: пробовать снова при показе окна.

## Мелочи

- **Хрупкое чтение события.** `KeyMonitor.swift:64` читает код клавиши до проверки типа события, в том числе для служебных событий. Сейчас это не ломается.
- **Hotkey.** Если ⌥⌘K не зарегистрировалась, ошибка молча игнорируется (`HotKey.swift:26`), а меню всё равно показывает ⌥⌘K.
- **Caps Lock.** Клавиша горит, только пока включён режим заглавных (`KeyboardView.swift:71`). Если Caps Lock переключает язык, его нажатие не видно.
- **Тесты.** Запускаются только длинной командой с флагом. Флаг можно прописать в `Package.swift`, чтобы работал обычный `swift test`.
- **Покрытие.** На логику нажатий (`KeyMonitor`) тестов нет, а баги 1–3 именно там.

## Что проверено и в порядке

- Компилятор не даёт ни одного предупреждения.
- Буфер в 4 символа на клавишу не переполняется: проверены все 264 установленные раскладки, длиннее 4 нет ни одной.
- Производительность: за 36 минут работы приложение потратило 4 секунды процессора. В момент замера нагрузка была 0 %, память — 87 МБ.
- Перехват нажатий работает только на чтение и только для клавиатуры.

## Рекомендация

Исправить баги 1–4 и хрупкое чтение события из мелочей.
